# Как передать L03 команде через GitHub

Работа подготовлена локально. В ваш репозиторий ничего автоматически не отправлено.

## Что загрузить

Внутри существующего репозитория создайте папку `l03_data_preparation`. Если команда уже использует другую структуру, согласуйте расположение со своей командой.

Добавьте в неё:

- `prepare_data.py`
- `test_prepare_data.py`
- `requirements.txt`
- `run_l03.ipynb` — без выводов с данными
- `README.md`
- `GITHUB.md`
- `VALIDATION.md`
- `.gitignore`

Не загружайте `raw/`, `processed/` и весь архив. По заданию закрытые исходники нельзя загружать на доску задач. Доступ к исходным и обработанным данным передавайте через согласованное закрытое хранилище команды. `.gitignore` помогает при работе через Git, но не защищает от ручной загрузки файлов через веб-интерфейс GitHub.

В `processed/cleaning_report.md` есть агрегаты по данным. Если правила команды разрешают публикацию таких отчётов в вашем репозитории, добавьте только этот отчёт отдельно в `l03_data_preparation/reports/cleaning_report.md`. Иначе передайте его вместе с данными в закрытом хранилище, а в Pull Request укажите согласованное место доступа.

## Самый простой способ: через сайт GitHub

1. Откройте командный репозиторий и создайте отдельную ветку `liza/l03-cleaning` из актуальной основной ветки команды.
2. Через добавление нового файла создайте `l03_data_preparation/README.md` и вставьте текст приложенного README. Это создаст папку.
3. Откройте эту папку, выберите загрузку файлов и загрузите остальные перечисленные выше файлы. Убедитесь, что не выбрали CSV или ZIP.
4. Файл `.gitignore` может быть скрыт на компьютере. Его можно создать через интерфейс добавления файла и скопировать содержимое из комплекта. Дополните его строкой `processed_*/`, если планируете дополнительные локальные запуски.
5. Сохраните изменения в свою ветку с сообщением `Add reproducible data cleaning for L03`.
6. Создайте Pull Request из своей ветки в основную ветку команды. Не объединяйте его без принятого в команде ревью.
7. В задаче L03 приложите ссылку на Pull Request, коротко опишите проверки и укажите, где лежат данные/отчёт. Передайте на ревью Арине, если это остаётся вашим распределением задач.

Названия кнопок могут отличаться в зависимости от языка интерфейса. Для этого способа Git на компьютере не нужен.

## Если репозиторий уже скачан на компьютер

В терминале перейдите в корень своей локальной копии. Сначала проверьте текущую ветку и незакоммиченные изменения:

```bash
git status
git switch -c liza/l03-cleaning
```

Если в рабочей папке есть чужие или незавершённые изменения, не сбрасывайте их. Скопируйте восемь файлов из списка выше в `l03_data_preparation`, сохранив существующие файлы проекта. Затем:

```bash
git add l03_data_preparation/prepare_data.py l03_data_preparation/test_prepare_data.py l03_data_preparation/requirements.txt l03_data_preparation/run_l03.ipynb l03_data_preparation/README.md l03_data_preparation/GITHUB.md l03_data_preparation/VALIDATION.md l03_data_preparation/.gitignore
git diff --cached --stat
git commit -m "Add reproducible data cleaning for L03"
git push -u origin liza/l03-cleaning
```

`git diff --cached --stat` должен показывать только выбранный код и документацию, без исходных и подготовленных датасетов. Затем откройте Pull Request на GitHub. Команда `git add .` здесь не нужна.

## Текст для описания Pull Request

Добавлена воспроизводимая подготовка трёх исходных CSV для L03: нормализация ID, пропусков и числовых полей, пометка спорных записей, безопасный справочник компаний и автоматический отчёт. Скрипт запускается из CLI, сохраняет все исходные строки и не выбирает произвольно неоднозначный профиль.

Проверки: три автоматических теста с граничными случаями, два полных запуска на одних входах, сравнение SHA-256 выходов, контроль строк/сумм и полное восстановление значений и типов после экспорта. Фильтр ритейла вынесен за рамки L03. Период и единицы платежей, смысл самопереводов и повторов требуют уточнения.

Исходные и подготовленные данные передаются отдельно в согласованном закрытом хранилище. Подробности проверок — в VALIDATION.md.

## Как коллеге повторить расчёт

Скачать вашу ветку, установить `requirements.txt`, положить три исходника в локальную папку `raw` и выполнить команду из README. Для подключения в общий проект согласовать имена выходных файлов и типы из `schema.json`. CSV не нужно вручную переименовывать в Excel.
