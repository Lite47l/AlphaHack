`.csv.gz` — обычный CSV, сжатый gzip. Его не надо переименовывать в `.xlsx`. Входные CSV: UTF-8-sig, `;`. Выходные CSV: UTF-8, `,`, пропуск записан пустым полем. Чтобы не потерять типы и ведущие нули, читайте так:

```python
from prepare_data import read_prepared
companies = read_prepared('processed', 'company_nodes')
payments = read_prepared('processed', 'payments_prepared')
```

Для соединения используйте `company_nodes`, а не все исходные варианты в `companies_prepared`:

```python
payer_info = companies[['SYNTHETIC_U', 'profile_status']].rename(columns={'SYNTHETIC_U': 'PAYER', 'profile_status': 'payer_status_check'})
result = payments.merge(payer_info, on='PAYER', how='left', validate='many_to_one')
```

## Правила обработки

- `source_row` — порядковый номер записи исходного CSV, начиная с 2 после заголовка. Сохраняется порядок исходных записей. При переносах строк внутри полей это номер записи, а не физической строки.
- ID и ОКВЭД остаются строками. Пробелы по краям удаляются; ведущие нули не удаляются.
- Пустые значения становятся NA. Из текстовых обозначений неизвестности обрабатываются только заранее известные маркеры географии физлиц.
- Числа переводятся через Decimal без float. Поддерживаются неотрицательные целые в диапазоне Int64. Дробные суммы не округляются: если они появятся в новой выгрузке, запуск остановится и правила нужно будет уточнить.
- Бинарные признаки принимают 0, 1 или NA. Отсутствующее значение не становится нулём.
- Строки не удаляются. Доказательств, что совпавшие платёжные строки являются ошибочным дублем, нет.
- Платежи самому себе сохраняются. Их смысл и единицы платежей не выдумываются.
- Все повторные ID компаний помечаются неоднозначными. Даже если будущие профили окажутся одинаковыми, автоматического объединения без отдельного правила нет.
- При отсутствии профиля сохраняются ID и связи. Для ambiguous/missing атрибуты неизвестны.
- ФНС и СПАРК сравниваются только когда известны оба значения. Если хотя бы одного нет, результат сравнения NA.
- Никаких дополнительных названий компаний, владельцев, поставщиков или стран импорта не выводится из косвенных признаков.

## Значение служебных полей

| Поле | Значение |
|---|---|
| `full_duplicate` | Строка входит в группу полностью совпадающих исходных строк; True у всех экземпляров |
| `normalized_duplicate` | Совпадение всех исходных полей после нормализации |
| `duplicate_pair` | Повтор пары физлицо–компания |
| `repeated_pair` | Повтор направленной пары отправитель–получатель |
| `self_payment` | PAYER равен BENEFICIARY |
| `pay_amt_missing`, `pay_cnt_missing` | Показатель отсутствует |
| `pay_amt_zero`, `pay_cnt_zero` | Известный показатель равен нулю; пропуск отмечается отдельно |
| `ambiguous_company_id` | В исходных профилях ID встречается более одного раза |
| `fts_country_review` | Флаг ФТС 1 без страны или 0 при известной стране; кандидат на уточнение |
| `workers_disagree` | True — известные категории различаются; False — совпадают; NA — сравнение невозможно |
| `profile_status` | matched — один профиль; ambiguous — несколько; missing — нет профиля |
| `in_profile` | ID есть в исходном справочнике, включая неоднозначный |

В `company_nodes` флаги исходных профилей для missing/ambiguous также неизвестны: ориентируйтесь на `profile_status`. В исходной таблице компаний флаг неоднозначности заполнен для каждой строки.

## Как читать отчёт

«Изменено строк» считает строку один раз, даже если обработано несколько полей. Учитывает нормализацию пропусков и значений, но не добавление служебных колонок. В `cleaning_changes.csv` одна строка — одно правило для одного поля. Счётчики разных правил могут пересекаться; их нельзя складывать как число уникальных строк.

`full_duplicate_extra_rows` — число копий сверх первого экземпляра, а не количество всех строк с флагом. Контрольные суммы — суммы доступных исходных чисел, без трактовки как рубли или экономический оборот. Пропуски дополнительно учитываются отдельными метриками и полным сравнением экспорта с исходным подготовленным DataFrame.
